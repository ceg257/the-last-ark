# THE LAST ARK：世界与连续场景设计

本文件是完整游戏路线与架构契约。当前交付为架构升级，**只有原试玩关可玩**；下列 Level 0、Level 1、Level 2、Endless 都是后续内容，不代表已经实现。

## 游戏定位与共同规则

人类最后的移民方舟寻找新家园。两名高等文明观察者不能直接驾驶方舟，只能改变周围天体的引力与斥力。游戏逐步从局部合作解谜走向大世界探索，仍为共享键盘、二维世界。

P1 使用 WASD / F 切换吸引，P2 使用方向键 / Enter 切换排斥。力场作用于所有配置为可受力的天体，不局限于飞船。大行星可缓慢推拉；未来太阳也可微弱推动；黑洞通过静态配置固定。飞船靠惯性、引力辅助和玩家配合航行，限速、危险碰撞、低速入港继续有效。

暂停允许部署玩家和观察预测。画面边缘不是物理边界，玩家与飞船可离开当前视野；任务若需要限制范围，必须明确配置独立世界区域。

## 完整游戏路线（内容规划）

| 路线 | 场景 ID | 内容与目标 | 出口与衔接 |
| --- | --- | --- | --- |
| 标题 | title | 开始、未来的章节入口；当前仅开放原试玩 | 明确的进入操作 |
| 独立原试玩 | prototype | 保留“绕行与制动”，一个可推拉行星、一颗陨石、一个空间港；用于物理回归 | 低速入港 completed，不自动跳进未实现章节 |
| Level 0 第一部分 | tutorial_part_1 | 分别学习吸引、排斥、开关叠加、暂停部署；先改变方舟航向再控制速度 | 完成配置的阶段目标后进入第二部分 |
| Level 0 第二部分 | tutorial_part_2 | 教会玩家天体也能被移动；一人修正方舟，一人搬动或清理障碍 | 完成移动天体目标，最后低速抵达空间站，衔接 Solar Exodus |
| Level 1：Solar Exodus | solar_system | 从太阳系内部向外逃离，包含太阳、行星、小行星带；借助行星引力和合作绕行 | 到达冥王星出口区域并满足任务条件，转入下一章节 |
| Level 2：Beyond the Horizon | black_hole | 绕过不可推动的黑洞；控制掠飞距离、速度、引力辅助方向 | 通过银河出口，转入广阔宇宙 |
| Endless Mode | endless | 探索不同星域；计划支持差异化天体组合、稀有地点和隐藏内容 | 星域间连续探索，虫洞可切换区域；不预设统一最终终点 |

Level 0 计划在完成阶段后显示教学提示、保存检查点，避免精确时机门槛。Solar Exodus 不要求一次装载整个太阳系。黑洞不可推动与太阳弱响应是能力配置的差异，不是玩家技能的例外判断。隐藏内容的生成规则、剧情文本、具体星球、星域布局与难度参数均未制作。

## 世界坐标与摄像机契约

- 每个实体 position / velocity 使用世界单位。Level.width / height 仅保留旧关卡参考尺寸，mapBounds 是导航参考范围；两者均不限制运动。
- missionBounds 可选，只有显式存在时才限制方舟。当前试玩未配置该边界。
- Camera 包含世界中心、缩放、视口 CSS 像素宽高。世界转屏幕：`screen = (world - camera.position) * zoom + viewport / 2`，逆变换对称。
- 镜头目标为飞船位置加速度前瞻（velocity × 0.65，长度最多 140）。跟随使用指数平滑；缩放范围 0.3–2。相机不进入物理积分、任务条件或区块需求计算。
- Canvas 按 ResizeObserver 更新视口和 DPR；渲染时应用世界矩阵，HUD、小地图、边缘箭头在屏幕空间绘制。
- 玩家离屏有 P1 / P2 箭头和距方舟的距离；目标离屏有绿色方向提示。小地图显示当前已加载实体、任务目标与镜头范围，允许负坐标和远处对象。
- 当前不限制两玩家与方舟的距离，没有自动传送或自动缩放；小地图范围会扩展，长距离协作体验仍需设计。

## 分层场景状态机

SceneId：title、prototype、tutorial_part_1、tutorial_part_2、solar_system、black_hole、endless。

GamePhase：ready、running、paused、failed、completed。例如 solar_system + paused 表示暂停太阳系任务，不是离开太阳系。

```text
title --明确开始--> prototype + ready --Space--> running
running --Space / 失焦--> paused --Space--> running
running --危险规则--> failed
running --目标完成 / complete 动作--> completed
failed / completed / 运行中 --R--> 当前检查点 + ready
任意游戏阶段 --Shift+R--> 当前关卡初始配置 + ready
任意游戏场景 --Esc--> title
运行中 --配置的世界触发条件 + transition--> 已实现目标场景 + ready
```

SceneController 持有场景与 GameState；场景注册表决定可用性及 Level 配置。后续场景登记为 planned，不可进入，也没有伪造的教学关。已完成试玩只显示胜利；不会提前进入新关卡。

切场景会创建独立状态，清空运行时目标与触发器记录，重置键盘、固定时钟和预测缓存，并将镜头定位到新出生点。单次触发器按 ID 去重；计划场景转场被拒绝且显示提示。当前所有转场规则只基于世界实体/区域/任务完成条件，不读取屏幕位置。

## 统一实体与能力配置

Entity 提供 id / kind / position / radius / layer；Body 增加速度和物理能力；Player 保留键盘运动字段及力场。玩家是统一实体类型的一员，但不进入天体积分列表。

| 类型 | 默认运动 | 发出引力 | 默认碰撞 | 力场响应 |
| --- | --- | --- | --- | --- |
| ship | dynamic | 是 | 自身为受检主体 | 1 |
| player | kinematic（键盘） | 否 | 无 | 0 |
| asteroid | dynamic | 是 | hazard | 1 |
| planet | dynamic | 是 | hazard | 0.18 |
| star | dynamic | 是 | hazard | 0.02 |
| black_hole | static | 是 | capture | 0 |
| station | static | 否 | 无 | 0 |
| wormhole | static | 否 | 无 | 0 |

- 默认值集中在 game/entities.ts。可用 motion、emitsGravity、collision、affectedByFields、response、density、gravityRadius、maxSpeed、captureRadius 覆盖。
- static 无论预设速度或受力参数为何都不移动，仍可作为引力源。kinematic 按预设速度运动，不接受加速度，适用于未来按轨迹移动的源。
- background 层强制静止、不施力、不碰撞，仅供渲染。hidden 只隐藏视觉，不取消物理。
- 触发实体由任务按 ID 引用；虫洞、空间站不需要实体碰撞才能触发。原试玩空间港已转为 station，使用 near_entity + maxSpeed + fullContainment 判断抵达。
- 半径和密度确定球体质量与引力。response 是游戏化加速度系数，不是严格真实天体动力学；它让大天体缓慢运动，不锁死行星。固定黑洞与可移动恒星由能力配置实现，积分器不检查特定天体名称。
- 兼容旧 Level.port：没有 mission 时自动转换为低速区域目标。新关卡应优先使用实体目标，避免显示位置与触发区域分离。

## 任务目标、触发器与检查点

Mission 分离 objectives 与 triggers。Objective 包含完成条件、可选前置目标、可选任务标记、导航目标；完成记录保存在 MissionState。必需目标全部完成时默认胜利，可用 completeOnObjectives=false 改成纯触发驱动。

已实现条件：

| 条件 | 用途 |
| --- | --- |
| enter_region | 从外部进入圆形或矩形区域；扫掠检测防止高速跳过 |
| inside_region | 当前实体在区域内 |
| speed_in_region | 当前完整/中心入区且速度不超过阈值 |
| entity_at | 指定天体被移到指定区域 |
| cross_band | 穿过圆形轨道带，含两个端点都在外部的情况 |
| near_entity | 接触/进入目标实体范围，支持移动目标、可选低速完整入港 |
| objective_complete / all | 阶段完成或多个条件同时满足 |

区域类型为 circle、rect、band。enter_region 在已经位于区域内时不会再次触发，inside_region 可以；低速条件必须在当前物理步结束时处于目标内，不能用高速扫过算完成。任务目标一旦完成便保持完成，适合阶段任务；若需要同时满足多个条件，应使用 all。

触发器动作：hint、checkpoint、transition、complete。每个触发器仅执行一次，前置目标可限制触发顺序。危险规则优先于目标完成。

检查点保存天体位置/速度、玩家、任务完成记录、触发记录、计时和关卡配置，不包含旧检查点的递归副本。恢复后暂停在 ready 并关闭力场，留给玩家调整；Shift+R 丢弃阶段进度并从头开始。当前为内存检查点，刷新页面不会保存。

原试玩的配置示例：方舟从外部进入世界矩形 x=640–700、y=100–280 时保存 after-bypass 检查点并给出制动提示。它不改变物理轨迹，不阻止从其他路线通关。任务框架和测试夹具能够表达教学/虫洞转场，但本次没有制作这些关卡。

## 物理、预测与性能

1. FixedClock 以 1/60 秒执行逻辑，与渲染帧率、镜头、DPR 解耦。每帧最多补算 15 步；慢设备可能丢弃超额实时时间，不增加单步长度。
2. Velocity Verlet 对同一步的全部已加载动态天体使用共同位置快照。先半步加速，再推进，再重算源位置并半步加速。保留软化距离、有限力场半径、单源/合加速度上限与速度上限。
3. 移动引力源自然形成引力弹弓，无额外“弹弓奖励”。固定源只弯曲轨迹；当前力场截断与硬限速是游戏化取舍。
4. 多分辨率 SpatialIndex 按引力影响 AABB 索引源；动态实体查询其位置附近的候选源，再用实际半径公式过滤。不是全宇宙两两计算。超大影响域使用较大格子。拥挤局部仍可能较昂贵，不承诺无限规模恒定时间。
5. 危险实体用扫掠 AABB 做碰撞候选查询，然后相对扫掠圆精确判定。离屏不移除陨石；捕获危险仍能吞噬动态天体。
6. 渲染对已加载实体做视野相交裁剪，仅绘制可见实际实体。小地图绘制的是导航点。显示裁剪绝不暂停物理。
7. 预测用独立状态副本调用同一 stepGame，包含移动引力源、任务、速度限制、碰撞。最多 12 秒，每秒更新 10 次；保持当前玩家位置/开关，遇到失败、完成或转场停止。没有 Worker 或大规模预测预算系统。

## 星域扩展接口（未连接加载器）

world/sectors.ts 定义 SectorKey、SectorData 和 SectorProvider.load / save / unload。区块边长 2048，负坐标采用 floor。worldSeed + 区块整数坐标生成确定种子，seededRandom 不依赖 Math.random 或加载顺序。

planSectors 将方舟与两位玩家作为需求焦点，默认规划至多 27 个相邻区块；镜头/缩放不是需求输入。接口已通过确定性测试，但当前试玩仍把全部 4 个天体留在内存，没有程序化生成、磁盘保存、异步加载调度或区块卸载逻辑。

未来实现约束：

- 卸载前保存动态状态，再次加载优先恢复，不可仅凭种子让移动过的天体回到初始位置。
- 区块加载需按引力/碰撞作用半径保留邻域和跨区源，不能只加载屏幕可见区；应给生成器配置最大作用半径，并纳入需求规划。
- 玩家分散时的加载上限、远场近似和未加载动态实体如何推进，需要单独设计与验证。当前 planSectors 是基础空间需求接口，不是完整物理正确的流式调度器。
- 加入生成器版本和存档版本，再保证跨版本复现。当前只保证同种子、同算法、同配置下序列可复现。
- 场景转场边界未来可放异步加载过渡；当前只支持同步已注册配置，不假装加载未来星域。
